# ADR 0005：多图像服务、模型能力与任务绑定

- 状态：已接受
- 日期：2026-10-21
- 替代：ADR 0002 的单份配置边界、ADR 0003 的单服务／单模型选择限制；其他数据生命周期约束继续适用。

Imagenia 允许管理多套 OpenAI Images 兼容服务，每个服务保存独立名称、地址、密钥和模型列表。模型声明支持的现有画幅、质量以及是否支持编辑；新增模型默认不支持编辑，旧配置迁移时保留已有编辑能力。生成和编辑显式选择服务、模型，允许把已有图片交给其他支持编辑的服务；不引入其他协议、任意尺寸或自动参数降级。

服务和密钥保存在数据目录 `config/services.json`，目录 `0700`、文件 `0600`，HTTP 不回显密钥。环境变量形成只读的“环境配置”，密钥不复制到文件。首次读取目录时迁移旧 `openai.json` 为默认服务，并保留旧设置接口作为兼容入口。旧文件在迁移后继续作为兼容镜像；删除旧服务时同时删除该文件，避免遗留隐藏的密钥副本。

任务提交时记录稳定服务／模型 ID、名称快照和连接指纹。指纹是用私有配置中随机签名密钥计算的 HMAC，绑定地址、API Key 和模型名，任务表不保存密钥。执行前验证指纹，一次性捕获连接信息并建立专属 provider，禁止分别读取不断变化的全局配置。修改默认项、名称或声明的能力不会重定向已提交任务。

同一服务存在 `pending` 或 `running` 任务时，禁止更换地址或密钥、移除或重命名已有模型、删除服务；允许改名、新增模型、调整能力声明、设置默认项和停用。停用只阻止新任务，已有任务继续执行。配置更改与任务提交在同一进程中通过锁串行化；数据库写事务保持短小，不在持有数据库写锁时等待配置锁。

重启后 `running` 仍标记中断，不自动重试；已有绑定但连接已改变的 `pending` 标记 `configuration_changed`。schema v4 升级时，旧 `pending` 因未记录可靠的服务绑定而明确失败，要求用户确认后重新提交，不推断它应调用哪套配置。旧图片、收藏及任务保留，缺少来源身份的历史记录显示“历史配置”。

默认项是一组全局服务／模型。浏览器记住最近选择；选择失效时显示错误，禁止悄悄回退到另一服务。失败任务可把原参数恢复到表单，由用户确认再提交；不自动重试或切换，以避免重复生成、传输和计费。

新资产与任务保存服务名称、模型等来源快照；删除服务只清理连接和密钥，保留图片与历史来源。任务保存用于手动重试的画幅／质量，不保存完整请求或密钥；删除关联资产时同时清除重试参数、提示词及来源／结果引用。

连接测试仅在用户点击时对所选已保存服务发出只读 `/models` 请求，不能据此宣称生成或编辑能力可用。常规自动化与本地交互验证使用临时数据和 fake provider，不产生真实生图费用。
