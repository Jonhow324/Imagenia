# Imagenia V1 产品与技术规格

- 状态：已发布到 GitHub Issue #1，测试接缝已确认
- 日期：2026-09-22

## Problem Statement

QwenPaw 用户目前缺少一个集成在 Console 中的本地 AI 图像工作台，无法在同一处完成图片生成、基于已有结果编辑、收藏和持续浏览。单独调用外部图像服务会造成图片分散、结果难以追踪，也缺少可靠的本地资产管理能力。

## Solution

构建一个 QwenPaw 全栈插件 Imagenia。插件提供单页面工作台，使用 OpenAI Images API 创建生成或编辑任务，将图片二进制保存在 QwenPaw 本机专属目录，将元数据和任务状态保存到 SQLite，并通过瀑布流展示全部图片，支持收藏筛选、详情查看和删除。

第一版以本地优先为原则：前端只调用插件后端，后端负责配置、任务队列、外部 API、数据库和图片资源访问。未来可在不改变本地资产模型的前提下增加上传同步接口。

## User Stories

1. 作为 QwenPaw 用户，我希望在 Console 中配置全局 OpenAI API Key，以便插件可以代表我调用图像服务。
2. 作为用户，我希望看到 API Key 是否已配置，但不希望界面回显完整密钥。
3. 作为用户，我希望输入提示词并选择画幅和质量，以便提交一个图片生成任务。
4. 作为用户，我希望提交后立即看到任务处于等待或生成中状态，而不是误以为页面失去响应。
5. 作为用户，我希望生成成功后看到新图片出现在资料库中。
6. 作为用户，我希望生成失败时看到安全且可理解的错误说明，而不是 Python 堆栈或服务商密钥信息。
7. 作为用户，我希望从已有图片的详情进入编辑流程，以便基于该图片继续创作。
8. 作为用户，我希望输入编辑提示词后生成一张新图片，同时保留原图不被覆盖。
9. 作为用户，我希望编辑结果能够显示其直接来源图片，以便理解创作关系。
10. 作为用户，我希望在瀑布流中浏览所有已生成和编辑的图片。
11. 作为用户，我希望图片列表使用分页或增量加载，以便图片很多时页面仍然可用。
12. 作为用户，我希望只筛选已收藏图片，以便快速找到重要结果。
13. 作为用户，我希望收藏或取消收藏图片，而不需要创建独立收藏夹。
14. 作为用户，我希望查看图片详情、提示词、尺寸、类型、模型和创建时间。
15. 作为用户，我希望删除图片时同时删除本地文件，避免持续占用磁盘空间。
16. 作为用户，我希望删除来源图片不会连带删除已经产生的编辑结果。
17. 作为用户，我希望 QwenPaw 重启后仍能看到已有图片和未完成的排队任务。
18. 作为用户，我希望 QwenPaw 重启时不会自动重复执行可能已经扣费的运行中任务。
19. 作为用户，我希望超过系统承载能力时得到明确提示，而不是无限等待。
20. 作为用户，我希望插件启动时自动执行数据库迁移，并在迁移失败时安全停止后端注册。
21. 作为用户，我希望测试配置连接时不会在未经确认的情况下消耗一次完整生图额度。
22. 作为维护者，我希望替换图像服务提供商时只修改 provider 适配层，不影响图片资产和任务领域模型。
23. 作为维护者，我希望日志可以帮助定位失败原因，但不包含 API Key、认证头、敏感请求参数或完整提示词。
24. 作为维护者，我希望插件卸载、重装和升级后，数据目录和数据库行为有明确且可测试的规则。

## Implementation Decisions

- 插件是同时包含后端和前端入口的 QwenPaw `general` 插件候选。
- 领域核心对象是 `ImageAsset`，表示生成或编辑结果；编辑创建新资产，并通过可空的来源资产引用建立直接来源关系。
- `GenerationJob` 表示异步生成或编辑任务。状态为 `pending`、`running`、`succeeded`、`failed`；第一版一个任务最多产生一个资产。
- 使用 SQLite 保存资产元数据、任务状态和收藏状态；使用显式 Repository 层和事务化、前向版本迁移，不引入 ORM。
- 图片二进制保存于插件专属本地目录，使用 UUID 文件名和年月目录；前端只能通过后端资源接口读取图片。
- 收藏直接作为 `ImageAsset` 的 `is_favorite` 与 `favorited_at` 状态，不建立独立收藏表。
- 插件启动时恢复 `pending` 任务；遗留 `running` 任务标记为 `failed/interrupted`，不自动重试。
- 使用一个后台 worker 串行处理任务。单任务总超时为 10 分钟，最多保留 50 个 `pending` 任务，超出返回 `429`。
- 第一版使用 OpenAI Images API，外部调用封装为 provider 适配器。
- 第一版只使用后端配置的一个默认模型；用户不能自由输入模型名称。
- 生成表单只暴露提示词、`square` / `landscape` / `portrait` 画幅和 `standard` / `high` 质量。
- 创建任务使用异步资源接口，返回 `202 Accepted` 和 `job_id`；前端每 1～2 秒轮询任务状态。
- 资产列表按 `created_at DESC, id DESC` 使用不透明游标分页，默认每页 30 条，并支持收藏和类型筛选。
- API Key 优先从环境变量读取，其次从插件数据目录中权限受限的私有配置文件读取；API 不返回完整密钥。
- 设置接口提供显式连接测试；不得在用户不知情时发起可能收费的完整生图请求。
- 删除资产时删除图片文件，解除后代资产的来源引用，并保留脱敏的最小任务记录；清除提示词、完整请求参数和结果引用。
- 前端采用单页面工作台，包含生成/编辑表单、任务状态、瀑布流和详情面板。任务完成后更新并高亮新资产，但不自动打开详情。
- 第一版只显示一级直接来源；复杂版本树、同步和多提供商能力留待后续版本。

## Testing Decisions

### 主要测试接缝

已确认以**插件后端 HTTP API 边界**作为最高测试接缝：使用临时数据目录、临时 SQLite 数据库和 fake image provider，验证用户可观察的请求、响应、持久化结果、文件结果和任务状态。这样可以同时覆盖 API、任务服务、Repository、资产存储和 provider 适配边界，避免把测试绑定到具体函数实现。

### 测试范围

- 插件配置：保存、覆盖、脱敏读取、环境变量优先级和连接测试不产生隐式生图。
- 数据库：首次迁移、重复启动、迁移失败、唯一约束、索引和数据保留策略。
- 生成：合法请求进入队列，任务完成后创建一个 `ImageAsset` 并保存文件。
- 编辑：必须引用已有资产，结果创建新资产，原图保持不变并建立直接来源关系。
- 任务生命周期：`pending`、`running`、成功、失败、超时、队列满和重启恢复。
- 资产：列表游标分页、收藏筛选、详情、受控内容访问和删除行为。
- 安全：错误响应和日志不包含 API Key、Authorization Header、完整请求参数或内部绝对路径。
- 插件生命周期：安装、加载、重启、覆盖安装、停用和卸载。

### 测试原则

测试外部行为，不测试 Repository 的私有实现或具体 SQL 排布。外部 OpenAI 调用必须由 fake provider 替代；另使用少量 provider adapter contract tests 验证真实请求映射，但不在常规测试中产生网络调用或费用。

当前仓库没有既有可复用的代码测试先例；因此测试基础设施和 fake provider 接缝应作为首个实现切片的一部分建立。

## Out of Scope

- 任意本地图片上传、蒙版和多图编辑。
- 批量生成、多结果任务、并发 worker、自动重试和取消任务。
- 多用户、按 Agent 或工作区隔离、权限系统和远程认证。
- 多模型选择、多服务商抽象的完整产品化能力。
- 标签、搜索、提示词历史、重新生成、多个收藏夹和完整版本树。
- 远程同步、对象存储、断点续传和服务器端图库。
- 回收站、恢复、复杂审计和自动内容审核。
- SSE、WebSocket 和实时推送。

## Future Extensions

第一版完成后可按使用反馈逐步扩展：提示词历史与一键重新生成、编辑版本对比、标签与搜索、多个收藏夹、图片详情页增强、多模型或多服务商切换，以及可恢复、可并发的生成任务队列。远程同步可增加仅负责上传的标准协议接口，但仍以本地 `ImageAsset` 为主数据，并要求独立服务器支持。

## Further Notes

实现前应再次核对目标 QwenPaw 稳定版本的插件清单、前后端入口、路由注册、配置 API、数据目录和前端构建约定。当前技术设计假设这些能力可以通过宿主公开插件 API 注册；不应依赖未公开的 QwenPaw 内部模块。

实现顺序建议为：插件加载骨架与 fake provider 接缝、SQLite 迁移与 Repository、任务 worker、生成 API、资产资源 API、编辑 API、前端工作台、收藏/删除/分页和完整生命周期测试。
